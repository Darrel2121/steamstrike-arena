# Технічна документація: Steamstrike: Tactical Arena
**Версія проекту:** 1.0.0  
**Дата оновлення:** Жовтень 2026  
**Стек:** Node.js (ESM), WebSocket (`ws`), HTML5 Canvas 2D, Vanilla JavaScript, REST API, Web Crypto  

---

## 1. Загальний огляд проекту

**Steamstrike: Tactical Arena** — це багатокористувацький тактичний 2D-шутер з видом зверху (Top-Down Shooter) у світі вікторіанського стімпанку. Геймплей натхненний механіками Bullet Echo та класичними тактичними іграми, де ключову роль відіграють туман війни, обмежений кут зору ліхтаря, акустична розвідка за звуковими хвилями та висока ціна помилки.

### Ключові особливості:
1. **Стімпанк-естетика:** латунні прилади, мідні труби, парові котли, манометри тиску (PSI), ліхтарі з вольфрамовими нитками, шестерні та вікторіанські залізничні термінали.
2. **Тактичний ліхтар (Directional Lantern FOV):** гравець бачить лише те, що освітлює його конічний ліхтар. Усе інше вкрите щільним туманом війни. Промені світла відбиваються від стін і не проникають крізь суцільні перешкоди.
3. **Акустичні хвилі (Acoustic Sound Waves):** кроки під час спринту, перезарядка зброї та постріли створюють акустичні кільця, які поширюються мережею і видно крізь туман війни всім гравцям у радіусі чутності.
4. **Високошвидкісна балістика та безперервна колізія (CCD):** снаряди рухаються з високою швидкістю (1100–1800 px/s) із прорахунком траєкторії променем між кадрами, що виключає проходження крізь стіни (bullet tunnelling).
5. **Вбудований редактор бойових карт (Map Editor):** створення власних арен, малювання стін, укриттів, спавнів, аптечок та декору з валідацією досяжності алгоритмом BFS.
6. **Різноманітні режими гри:**
   * Кожен за себе (Остаточна смерть / Battle Royale).
   * Командний бій (Остаточна смерть / Team Elimination).
   * Кожен сам за себе (З відродженням / Deathmatch до 10 кілів).
   * Командний бій (З відродженням / Team Deathmatch 2v2 до 15 кілів).
7. **Автономний ШІ ботів:** боти орієнтуються за звуками, використовують ліхтарі огляду, займають укриття та патрулюють арени.
8. **Система прогресії та прокачки (Майстерня):** покращення характеристик бійця (HP, швидкість, ліхтар) та арсеналу (збиток, скорострільність, перезарядка, місткість магазину) з обмеженням покупок для зареєстрованих акаунтів.

## 2. Архітектура системи та мережевий стек

Проект побудовано за клієнт-серверною архітектурою з **авторитарним сервером** (Authoritative Server Architecture). Клієнти не мають права самостійно вирішувати питання нанесення шкоди, переміщення крізь перешкоди чи підбору предметів.

```
                           [ КЛІЄНТИ БРАУЗЕРІВ ]
                       /            |            \
          Client 1 (Host)     Client 2 (Peer)    Client N...
                 \                  |                  /
             WebSocket (JSON)   HTTP (REST)   WebSocket (JSON)
                   \                |                /
                    ▼               ▼               ▼
          +---------------------------------------------------+
          |                  HTTP & WS SERVER                 |
          |                  (server/index.js)                |
          +---------------------------------------------------+
          |   REST API:               GameServer Manager:     |
          |   - /api/auth/*           - Client connection     |
          |   - /api/profile/*        - Room dispatching      |
          |   - /api/rooms            - Heartbeat / Ping      |
          +---------------------------------------------------+
                                    |
                    +---------------+---------------+
                    ▼                               ▼
       +-------------------------+     +-------------------------+
       |   Authoritative Room    |     |   ProfileStore (DB)     |
       |     (server/Room.js)    |     |  (server/db/Profile.js) |
       +-------------------------+     +-------------------------+
       | - 30Hz Simulation Loop  |     | - Atomic file write     |
       | - Physics & Collisions  |     | - Mutex Promise queues  |
       | - Anticheat Clamping    |     | - Google / Guest index  |
       | - Bot AI Controllers    |     +-------------------------+
       | - Spatial Visibility    |
       | - Snapshot Broadcast    |
       +-------------------------+
```

### 2.1. Авторитарний цикл симуляції (30 Hz Tick Rate)
* Сервер запускає ігровий таймер із частотою **30 кадрів на секунду** (`TICK_INTERVAL_MS = 33.33ms`).
* Кожен тік виконує послідовність:
  1. Збір та валідація вхідних команд керування від усіх підключених клієнтів (`processInputs`).
  2. Оновлення кінематики гравців із контролем швидкості (Anticheat Speed Limiter).
  3. Тік штучного інтелекту ботів (`Bot.update`).
  4. Переміщення снарядів та детекція влучань променями CCD.
  5. Перевірка колізій з аптечками та ящиками боєприпасів.
  6. Оновлення стану кіл звукових хвиль та очищення згаслих хвиль.
  7. Перевірка умов перемоги відповідно до активного ігрового режиму.
  8. Формування та розсилка снапшота стану світу (`S2C_GAME_STATE`).

### 2.2. Мережевий протокол (`shared/Protocol.js`)
Транспорт базується на WebSockets. Повідомлення серіалізуються у компактний JSON-формат із заголовками `t` (тип пакета), `d` (дані) та `ts` (мітка часу).

#### Клієнт -> Сервер (C2S):
* `C2S_JOIN_LOBBY`: підключення до кімнати за кодом або назвою.
* `C2S_CREATE_ROOM`: створення нової кімнати з вибором карти, режиму та параметрів.
* `C2S_PLAYER_INPUT`: вектор руху `(vx, vy)`, кут прицілу `aimAngle`, біг `sprint`, стрільба `shooting`, перезарядка `reload`.
* `C2S_TOGGLE_READY`: готовність бійця в лобі.
* `C2S_START_MATCH`: запуск матчу хостом.
* `C2S_CHANGE_GAME_MODE`: зміна режиму гри хостом.
* `C2S_CHANGE_TEAM`: вибір команди (`team1` чи `team2`).
* `C2S_PING`: вимірювання затримки мережі (RTT / Ping).

#### Сервер -> Клієнт (S2C):
* `S2C_LOBBY_STATE`: склад кімнати, готовність гравців, карта, режим, статус хоста.
* `S2C_MATCH_INIT`: координати спавну, параметри карти, ідентифікатор гравця, ліміти швидкості.
* `S2C_GAME_STATE`: снапшот 30 Hz із позиціями видимих гравців, снарядами, очками, хвилями звуку.
* `S2C_MATCH_OVER`: підсумок бою, переможець, статистика фрагів та нагороди (XP, Scrap, Cores).
* `S2C_ELIMINATION`: повідомлення про ліквідацію бійця.
* `S2C_ERROR`: помилка валідації (наприклад, кімната заповнена).

## 3. Тактичні механіки та фізичний рушій

### 3.1. Паровий ліхтар (Directional Lantern FOV) та 2D Raycasting
Кожен боєць має напрямлений ліхтар із сектором освітлення **90 градусів** (`LANTERN_ANGLE = PI / 2`) та базовим радіусом **420 px** (з можливістю прокачки до 495 px у Майстерні).

* **Побудова геометрії ліній огляду (`RaycastVisibility.js`):**
  1. Карта бойової арени перетворюється на масив відрізків стін та перешкод (`extractSegmentsFromMap`).
  2. Алгоритм випускає пучок променів до кожної кінцевої точки відрізка (з мікрозміщеннями `±0.0001` рад).
  3. Знаходяться найближчі точки перетину кожного променя зі стінами за формулою перетину відрізків:
     $$t = \frac{(q_x - p_x)s_y - (q_y - p_y)s_x}{r_x s_y - r_y s_x}$$
  4. Отриманий багатокутник перетину формує маску світла Canvas (`clip()`), за межами якої простір залишається в абсолютній темряві.
* **Багатоліхтарна видимість:** на екран виводяться також конуси світла ліхтарів союзників та супротивників, якщо джерело ліхтаря потрапляє в поле зору гравця.

### 3.2. Акустична система звукових хвиль
Коли персонаж рухається в режимі спринту (`sprint: true`) або здійснює постріл, сервер реєструє подію звуку:
* **Кроки (Footstep):** початковий радіус 12 px, розширення до 120 px зі швидкістю 180 px/s, тривалість життя 650 мс.
* **Постріли (Gunshot):** початковий радіус 20 px, розширення до 450 px зі швидкістю 600 px/s, тривалість життя 1100 мс.
* Звукові хвилі транслюються через мережевий снапшот і малюються на клієнті пульсуючими концентричними латунними кільцями крізь туман війни, видаючи координати джерела шуму навіть за стінами.

### 3.3. Балістика Continuous Collision Detection (CCD)
Для запобігання прольоту куль крізь стіни (tunnelling effect):
1. Кожен снаряд на кожному кроці симуляції описує відрізок переміщення від попередньої позиції $\vec{P}_0$ до нової $\vec{P}_1 = \vec{P}_0 + \vec{V} \cdot \Delta t$.
2. Проводиться тест перетину відрізка траєкторії снаряда з усіма лініями стін та прямокутниками перешкод.
3. Перевіряється перетин із колами колізій гравців за методом мінімальної відстані від точки до відрізка.
4. При влучанні обчислюється точна точка контакту, кулі наносять шкоду відповідно до таблиці зброї, генерують сплеск іскор та знищуються.

### 3.4. Манометр витривалості (Steam PSI Manometer)
* Спринт витрачає тиск пари в ранці персонажа (зі 100 PSI до 0 за 4.5 секунди).
* При вичерпанні пари спринт вимикається, швидкість падає до базової ходи.
* У режимі спокою або ходи тиск пари відновлюється через випускний клапан (Passive Vent Recovery).

## 4. Режими гри (Game Modes)

| Код режиму | Назва режиму | Відродження | Умова перемоги |
|---|---|---|---|
| `solo_elim` | Кожен за себе (Остаточна смерть) | Ні (Permadeath) | Останній живий гравець на арені |
| `team_elim` | Командний бій (Остаточна смерть) | Ні (Permadeath) | Повне знищення команди супротивника |
| `ffa_dm` | Кожен сам за себе (Deathmatch) | Так (3 сек) | Перший, хто набере 10 ліквідацій |
| `team_dm` | Командний Deathmatch (🐺 vs 🦊) | Так (3 сек) | Перша команда, що набере 15 ліквідацій |

У командних режимах гравці розподіляються між фракціями **Вовків (Team 1)** та **Лисиць (Team 2)**, отримуючи кольорову диференціацію ліхтарів та HUD.

## 5. Вбудований редактор бойових карт (Battle Map Editor)

Редактор бойових карт дозволяє створювати, редагувати, зберігати та імпортувати рівні безпосередньо у браузері.

### 5.1. Формат схеми карти (`shared/MapSchema.js`)
Карта серіалізується у структурований JSON:
```json
{
  "version": "1.0",
  "name": "The Grand Zeppelin Docks",
  "theme": "hangar",
  "width": 32,
  "height": 32,
  "tileSize": 40,
  "tiles": [1, 1, 1, ..., 0, 0, 1],
  "spawns": [
    { "id": "player_1", "type": "player", "col": 4, "row": 4 },
    { "id": "bot_1", "type": "bot", "col": 27, "row": 27 }
  ],
  "pickups": [
    { "type": "ammo", "col": 16, "row": 12 },
    { "type": "health", "col": 16, "row": 20 }
  ],
  "decorations": [
    { "type": "gear", "col": 6, "row": 6 },
    { "type": "vent", "col": 10, "row": 16 }
  ]
}
```

### 5.2. Типи тайлів та об'єктів:
* **Тайли:** `0` — вільна підлога (Floor), `1` — глуха стіна (Wall), `2` — укриття/ящики (Obstacle).
* **Спавни:** точки старту гравців (`player`) та ботів (`bot`).
* **Предмети (Pickups):** аптечки відновлення міцності котла (+50 HP) та ящики патронів.
* **Стімпанк-декор:** шестерні (`gear`), парові решітки (`vent`), мідні труби (`pipes`), ліхтарні стовпи (`lantern`), тискові резервуари (`tank`), тріщини підлоги (`crack`), покажчики (`sign`), міський чагарник (`bush`).

### 5.3. Пресетні бойові арени:
1. **The Clockwork Foundry** (20 × 20, 800 × 800 px) — компактна індустріальна ливарня з центральним котлом.
2. **The Ironworks Catacombs** (28 × 28, 1120 × 1120 px) — підземний лабіринт шахт, цегляних арок і засідок.
3. **The Grand Zeppelin Docks** (32 × 32, 1280 × 1280 px) — велетенський ангар дирижаблів з причальними пірсами.
4. **The Alchemical Citadel** (36 × 36, 1440 × 1440 px) — фортеця з 4 бастіонами та плацом.
5. **The Steam Rail Terminal** (40 × 24, 1600 × 960 px) — видовжений залізничний вокзал з потягами та перонами.

### 5.4. Алгоритм валідації (BFS Flood Fill):
Перед запуском матчу карта перевіряється функцією `validateMap`:
* Наявність мінімум одного спавну гравця та одного спавну бота.
* Відсутність накладання спавнів або предметів на суцільні стіни.
* **Тест зв'язності (Reachability Invariant):** алгоритм пошуку в ширину (BFS) перевіряє, що від початкового спавну можна вільно дістатися до всіх інших спавнів і точок підбору лише через клітинки підлоги `0`.

## 6. Штучний інтелект ботів (Autonomous Bot AI)

ШІ ботів реалізовано як детермінований скінченний автомат (Finite State Machine) із сенсорним сприйняттям:

```
                      +-------------------+
                      |      PATROL       | <-------------+
                      | (Обхід контрольних|               |
                      |      точок)       |               |
                      +-------------------+               |
                         /             \                  |
           Почув звук   /               \ Побачив ворога  | Втрата
           хвилі кроків/                 \ у конусі FOV   | контакту
                      ▼                   ▼               |
         +-------------------+     +-------------------+  |
         |    INVESTIGATE    |     |      COMBAT       | -+
         | (Рух до джерела   | --> | (Прицілювання,    |
         |      шуму)        |     |  стрейф, вогонь)  |
         +-------------------+     +-------------------+
                                            |
                                 Низький HP | (< 35%)
                                            ▼
                                   +-------------------+
                                   |      RETREAT      |
                                   | (Пошук укриття    |
                                   |   та аптечки)     |
                                   +-------------------+
```

* **Сенсорика:** боти "бачать" супротивників лише тоді, коли між ними немає глухих стін (перевірка відрізком `circleSegmentIntersect`) і ціль потрапляє у кут огляду.
* **Слух:** реєстрація звукових хвиль дозволяє боту розвернутися та розпочати рух до місця підозрілої активності.
* **Адаптивна влучність:** бот розраховує кут випередження з невеликим випадковим розсіюванням, щоб дати гравцеві шанс на маневр.

## 7. Система прогресії, економіка та авторизація

### 7.1. Арсенал стімпанк-зброї:
* **Revolver «Peacemaker»:** базова надійна зброя високої точності.
* **Steam Carbine:** автоматична гвинтівка високого темпу стрільби.
* **Heavy Blunderbuss:** дробовик із залпом із 5 куль на короткій дистанції.
* **Pneumatic Needle Gun:** снайперська голчаста рушниця екстремальної швидкості кулі (1800 px/s).

### 7.2. Прокачка характеристик (до 5 рівнів кожна):
* **Міцність котла (Health):** збільшення базового здоров'я з 100 до 125 HP.
* **Тиск поршнів (Speed):** збільшення швидкості переміщення з 180 до 200 px/s.
* **Оптичні лінзи (Lantern):** збільшення дальності освітлення з 420 до 495 px.
* **Параметри зброї:** шкода (+8%/рівень), скорострільність (+10%/рівень), швидкість перезарядки (-10%/рівень), ємність магазину.

### 7.3. Політика захисту та авторизації:
* **Гостьовий акаунт (Guest Account):** створюється автоматично при вході, дозволяє грати у всіх режимах, накопичувати досвід (XP), металобрухт (⚙️ Scrap) та ядра (💎 Cores).
* **Обмеження на покупки:** кнопки покращень характеристик і відкриття креслень зброї заблоковані для гостей (`🔒 Увійти для апгрейду`). Серверні ендпоінти `/api/profile/upgrade/*` повертають статус `403 Forbidden`, вимагаючи реєстрації.
* **Авторизація через Google:** використання Google Identity Services (GSI) для безпечного входу в один клік без необхідності введення паролів.
* **Атомарне сховище (`ProfileStore.js`):** захист від гонки процесів (Race Conditions) через ланцюжки черг Promise Mutex та безпечний запис у файл через тимчасовий буфер із наступним перейменуванням.

## 9. Інструкція з розгортання та запуску

### 9.1. Системні вимоги:
* **ОС:** Windows 10/11, Linux (Ubuntu 20.04+), macOS.
* **Середовище:** Node.js v18.0.0 або новішої версії (підтримка native fetch та ES modules).
* **Порт:** 3000 (або змінна оточення `PORT`).

### 9.2. Локальний запуск для розробки:
1. Відкрийте термінал у кореневому каталозі проекту:
   ```powershell
   cd d:\!Annet_game
   ```
2. Запустіть сервер:
   ```powershell
   node server/index.js
   ```
3. Відкрийте браузер за адресою:
   `http://localhost:3000`

### 9.3. Запуск автоматичних тестів:
Для виконання всіх 228 модульних, граничних та інтеграційних тестів виконайте:
```powershell
node tests/runner.js
```

### 9.4. Онлайн-доступ (Порти, Домен та Тунелювання):
* **Швидкий тест через тунель (Pinggy / Cloudflare Tunnel / Ngrok):**
  ```powershell
  ssh -p 443 -R0:localhost:3000 -o StrictHostKeyChecking=no a.pinggy.io
  ```
* **Прив'язка власного домену (наприклад, через VPS / Nginx reverse proxy):**
  Конфігурація віртуального хосту Nginx:
  ```nginx
  server {
      server_name yourdomain.com;

      location / {
          proxy_pass http://127.0.0.1:3000;
          proxy_http_version 1.1;
          proxy_set_header Upgrade $http_upgrade;
          proxy_set_header Connection "upgrade";
          proxy_set_header Host $host;
          proxy_cache_bypass $http_upgrade;
      }
  }
  ```

## 10. Автоматизоване тестування та надійність

Проект покритий **228 автоматизованими headless-тестами**, які перевіряють:
1. **Tier 1 (Unit):** серіалізація карт, валідація BFS flood fill, ізоляція спавнів, утиліти математики.
2. **Tier 2 (Boundary & Stress):**
   * Фаззинг десеріалізації пакетів (5 000 циклів мутацій, захист від Prototype Pollution).
   * Стійкість сокетів під час шторму з'єднань (50–150 одночасних підключень).
   * Стрес-тест античиту (clamping швидкості при спробі спідхаку до 300 px/s).
   * Стійкість геометрії (1 000 ітерацій геометричного фаззингу променів).
   * Атомарність ProfileStore при одночасних паралельних транзакціях.
3. **Tier 3 (Integration):** взаємодія ліхтарів союзників, швидкісні снаряди CCD, манометр тиску пари, нарахування очок у Team Deathmatch.
4. **Tier 4 (E2E Lifecycle):** 10-етапна повна симуляція матчу: вхід -> спавн -> розвідка за звуком -> бій -> укриття -> перезарядка -> ліквідація -> фінал -> нарахування нагород.

**Результат проходження тестів:** 228 / 228 (100% успіх).
